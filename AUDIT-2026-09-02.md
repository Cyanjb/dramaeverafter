## 3. Issues, ranked

### HIGH

**H1. The site claims freshness the data does not have.**
3,334 of 3,513 titles were last verified in July. 3,111 of 3,297 availability
rows were last checked in July. Every view_count_date is July. The homepage
rail is titled "Most watched right now" and every where-to-watch page says
"Checked August 2026" (it will say "Checked September 2026" on the next build,
because the stamp comes from the build clock, not from last_checked). The
weekly scrape in the pipeline skill has not run in seven weeks.
Fix: derive "Checked" from the row's last_checked; rename the rail "Most
watched" until a second snapshot exists; run the scrape.

**H2. snapshots.csv has no dates.** All 2,659 rows have an empty `date`
column. Without dates the table cannot support "trending", "hot this week", or
any change-over-time claim, which is the only route to the "right now" rail
being true. Fix: backfill from view_count_date, and make the merge step write
the date.

**H3. The whole database and toolchain are published on the domain.** The repo
root is the Netlify publish directory, so `data/titles.csv`, `generator/`,
`references/adapters.md`, the staging caption files (which hold verbatim
platform synopses in their FACTS blocks), 258 files of design skills under
`.claude/skills` (11 MB) and `design-system/` all deploy to dramaeverafter.com.
The repo is public anyway, but serving the CSV at a URL on the brand domain
makes wholesale copying a one-line fetch, and it contradicts the ai-train=no
posture. Verify with `curl -I https://dramaeverafter.com/data/titles.csv`.
Fix: add `_redirects` lines returning 404 for `/data/*`, `/generator/*`,
`/references/*`, `/design-system/*`, `/.claude/*`, `/.design-sync/*`, `/*.md`.
Longer term, publish from a `site/` folder.

**H4. No Open Graph, no Twitter card, no favicon, on any page.** The audience
lives on Reddit and Facebook. Every shared link renders as a bare URL. Posters
exist for 3,037 titles, so og:image is one template change. Add og:title,
og:description (the caption hook), og:image (poster_ref), og:url, and a
favicon + apple-touch-icon.

**H5. No analytics and no Search Console review on record.** Nothing measures
traffic. The parked ratings idea, the where-to-watch question (H7) and the
"which platform to fill next" question all depend on knowing what people
land on. Add Plausible or Umami (script from cdnjs is fine) or Netlify
Analytics, and read Search Console coverage once.

**H6. Backup of the one irreplaceable file is still on one PC.** The
gitignored `_quarantined_synopses.json` (the fact source for every caption)
exists only on Cyan's machine and in a zip on the same machine. Open since
15 Aug. Copy the zip to the Drive folder today. Keep it out of the public
repo; it is platform text.

### MEDIUM

**M1. 3,513 where-to-watch pages are thin near-duplicates of the title pages.**
Each is one sentence plus two FAQ items, self-canonical, and they are 37% of
all URLs. Google is likely to file most as "crawled, not indexed", which
dilutes crawl budget for the pages that matter. Decide after reading Search
Console: either canonical them to the title page, or 301 them.

**M2. GoodShort trope soup, known and queued.** GoodShort averages 17.3 tropes
per title (ReelShort 2.1); 1,491 titles carry 15 or more. New: NetShort has
21 titles at 15+ too. Wrong tropes leak onto browse pages. Waiting on Cyan's
go.

**M3. Generic meta descriptions and a mid-word JSON-LD cut.** Every title page
uses "X: where to watch, cast and tropes. Updated August 2026." while 825
titles have a real synopsis and 215 a written hook. The JSON-LD description is
sliced at 160 characters mid-word ("doesn't s"). Use the hook + body for the
meta description and cut at a word boundary.

**M4. Coverage gaps by reach.** Across all titles: 2,688 (77%) have no synopsis,
2,058 (59%) no cast, 452 no watch link, 261 no platform, 638 no trope, 476 no
poster. Top 600 by views, which carry 98% of all views: 50 no synopsis, 28 no
cast, 54 no tropes, 61 no episode count. That top-600 list is small and
finite; it is the right next target after the top-300 captions.

**M5. PineDrama is still linked from 65 title pages** and `/apps/pinedrama.html`
is live, against the "official platforms only" ruling. 63 titles have it as
their only source.

**M6. Three stale branches carry 80 to 107 divergent commits each**
(`claude/deterministic-build`, `claude/drama-ever-after-resume-7g4fwq`,
`claude/popular-actors-rail`). Their content is in main (PR #1 was squashed),
but a future session that "merges" one would rewrite ~10,000 files. Delete
them. `claude/frontend-design-ui-ux-skills-ghwn2s` is merged and can go too.

**M7. Dead ends on the site.** The contact form never submits (client-side
only) and routes to hello@ and fix@dramaeverafter.com, which I could not
confirm exist. The blog has no posts but sits in the main nav with a
newsletter "Sign me up" that goes nowhere. "Report it" on where-to-watch pages
leads to the same contact page. Netlify Forms (free tier) closes all three;
the Zoom notes from 12 Aug already document the workflow.

**M8. Affiliate disclosure without an affiliate programme.** Every title page
says "We may earn a commission". 574 ReelShort watch links carry no affiliate
parameter; platforms.csv marks only ReelShort as having a programme. Either
join the programmes or soften the copy until then.

**M9. Cloud sessions cannot reach any external host.** Even example.com
returns 000. Every scrape, caption fetch and live-site check must run in a
local session, which has cost several sessions already. Either set the
environment network policy at claude.ai/code to allow the platform domains,
or move the scrape to GitHub Actions (see section 5).

### LOW

**L1. No 404 page.** Netlify's default serves for the 73 deleted PineDrama
twins and any typo. A branded 404.html with the search box costs one file.
**L2. No privacy page.** Needed the moment analytics or forms go in (POPIA
and GDPR both apply to an EU-indexed site).
**L3. Payload weight.** `search-index.json` is 1.3 MB and is fetched by Browse
and My List; `actors/index.html` is 565 KB. Netlify compresses, but this is a
phone audience. Split the index or lazy-load past the first screen.
**L4. Sitemap has no lastmod.** last_verified is on disk; emit it.
**L5. Posters are hotlinked from six platform CDNs.** If any changes
referrer rules, thousands of posters vanish (the onerror fallback hides the
break). Acceptable for now; note the risk.
**L6. No `_headers` file.** Add Referrer-Policy, X-Content-Type-Options and a
long cache for style.css.
**L7. Documentation drift.** README says eight CSVs (there are ten) and still
describes the drag-into-GitHub workflow; the pipeline skill still says
"web_fetch only, platforms not reachable from bash" and "hand back a zip",

"7. DEA TASKS" (last edited 16 Aug) still lists the Cancel the Wedding line
that commit `26ebdae8` resolved. Craft references "7. DEA GAPS", "7. DEA
TROPES WANTED" and "3. Data Schema" that are not in the DEA folder.
**L8. 90 match_queue rows await a ruling** (77 pending, 13 blank). 14 fused

**L9. Gmail.** The connected inbox (cyan.ai.art@gmail.com) holds no

## 4. What you may be missing

1. **A feedback loop.** No analytics, no Search Console read, no form
   submissions. Every prioritisation so far is by view count scraped in July.
2. **Social sharing.** The audience shares links in threads; the links have
   no preview (H4).
3. **A running refresh.** The pipeline is designed as weekly and has not run
   since mid-July. The harvest scripts use only the standard library
   (`urllib.request`), so they would run unattended on a GitHub Actions
   runner, which has open egress. A weekly cron that scrapes, merges, writes
   snapshot dates, rebuilds and commits would make "Most watched right now"
   true and make trending possible. Keep the politeness rules from the skill.
4. **Ways for people to give you data.** The Craft "6. Data Sources" doc
   named two plays (actors self-report, fans become the data team). Neither has
   a working input on the site. Netlify Forms is the cheapest version.
5. **Spice level.** Blank on all 3,513 titles, no platform publishes it, and
   it is the question this audience asks first. One-tap vote via Netlify Forms
   was already assessed as viable. Parked, correctly, behind traffic (H5).
6. **A privacy page and a working contact mailbox** before any of the above.
